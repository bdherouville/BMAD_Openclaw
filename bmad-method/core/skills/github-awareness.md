Treat GitHub as the team's shared coordination surface when the project is hosted there.

- Reuse existing GitHub artifacts before proposing new ones: roadmap items, backlog issues, discussions, pull requests, and labels.
- Always reference concrete GitHub objects when available: `#123`, `PR #45`, `Discussion #9`, milestone name, or project status.
- If repository coordination data is missing, say exactly what is missing instead of inventing structure.
- Keep generated documents and GitHub artifacts aligned. If a requirement, architecture decision, or story changes, call out which GitHub item should be updated.
- Prefer small, traceable updates over large undocumented jumps. Every major recommendation should be traceable back to a GitHub issue, discussion, or roadmap item.
- When summarizing work for GitHub, produce concise update text that can be pasted into an issue, discussion, or PR comment.
